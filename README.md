# beskrovnyy.pro

Персональный сайт и блог, созданный на [Astro](https://astro.build/).

## Требования

- Проверенная версия Node.js — **24.11.0**, закреплена в `.nvmrc`;
- npm — **11.6.1**, поставляется с этой версией Node.js и указан в `packageManager`.

Минимальные совместимые версии из требований Astro: Node.js 22.23.4 и npm 9.6.5.
Для повторения проверенной сборки используй Node.js 24.11.0 и npm 11.6.1.

## Установка

Перейди в каталог проекта. Если используешь [nvm](https://github.com/nvm-sh/nvm),
установи и выбери версию Node.js из `.nvmrc`:

```bash
nvm install
nvm use
```

Без nvm установи Node.js 24.11.0 с npm 11.6.1 самостоятельно.
Затем установи зависимости из зафиксированного `package-lock.json`:

```bash
npm ci
```

`npm ci` использует версии из lock-файла, пересоздаёт `node_modules/` и
останавливается, если `package.json` расходится с lock-файлом. Используй эту
команду при настройке проекта и в CI.

Чтобы добавить или обновить зависимость, используй `npm install` с именем и
нужной версией пакета. После проверки сборки сохраняй `package.json` и
`package-lock.json` в одном коммите.

Папки `.astro/`, `dist/` и `node_modules/` создаются автоматически и не хранятся
в Git. Файлы типов Astro появляются при `npm run check`, `npm run dev` или
`npm run build`. Pagefind устанавливается через npm вместе с бинарником для
текущей платформы; отдельный `pagefind.exe` в корне проекта не нужен.

## Запуск в режиме разработки

Для обычной разработки запусти локальный сервер:

```bash
npm run dev
```

После запуска сайт будет доступен по адресу:

<http://localhost:4321>

Astro автоматически обновляет страницу после изменений в исходных файлах.

В режиме разработки поиск Pagefind не работает, потому что индекс поиска ещё не создан. Этот режим удобен для работы с вёрсткой, страницами и стилями.

## Production-сборка и индекс поиска

Для создания production-сборки выполни:

```bash
npm run build
```

Команда выполняет два шага:

1. Astro собирает сайт в каталог `dist/`;
2. Pagefind анализирует готовые HTML-страницы и создаёт индекс поиска в `dist/pagefind/`.

В результате Pagefind индексирует страницы сайта и создаёт файл:

```text
dist/pagefind/pagefind.js
```

Именно этот файл загружает компонент поиска.

## Просмотр production-сборки

Чтобы посмотреть сайт вместе с работающим поиском, сначала собери его,
затем запусти сервер:

```bash
npm run build
npm run preview
```

`preview` использует готовый каталог `dist/`, без повторной сборки и индексации. После запуска открой:

<http://localhost:4321>

После изменений выполни `npm run build` ещё раз и обнови страницу в браузере.

## Какой режим использовать

- `npm run dev` — быстрая разработка с автоматическим обновлением страницы; поиск Pagefind в этом режиме недоступен.
- `npm run build` — собрать сайт и создать индекс Pagefind без запуска сервера.
- `npm run preview` — просмотреть уже собранную production-версию локально; этот режим нужен для проверки поиска.

## Проверки качества

Перед коммитом выполни:

```bash
npm run verify
```

Команда последовательно проверяет SCSS и типы Astro, запускает тесты поиска и
навигации, собирает сайт с Pagefind и проверяет готовый `dist/`. Проверки сборки
охватывают заголовки, языки страниц и индекса, локальные ссылки и ресурсы,
форматы и размеры изображений. Если один шаг не прошёл, следующие не запускаются.

GitHub Actions выполняет ту же команду после `npm ci` на каждом push и pull request,
используя Node.js из `.nvmrc`. Для сборки с индексом используй `npm run build`;
прямой вызов `astro build` создаёт только страницы Astro.

## Основные команды

| Команда | Назначение |
| --- | --- |
| `nvm use` | Выбрать закреплённую версию Node.js, если установлен nvm |
| `npm ci` | Установить зависимости из lock-файла |
| `npm run dev` | Запустить сервер разработки |
| `npm run lint` | Проверить SCSS без предупреждений |
| `npm run check` | Проверить типы и диагностику Astro |
| `npm test` | Проверить поиск и закрытие навигационных панелей |
| `npm run test:build` | Проверить готовый каталог `dist/` |
| `npm run build` | Собрать production-версию сайта |
| `npm run preview` | Просмотреть production-сборку локально |
| `npm run verify` | Выполнить все проверки и сборку, как в CI |

## Структура проекта

- `src/pages/` — страницы и записи блога;
- `src/assets/` — изображения и другие исходные ресурсы;
- `public/` — статические файлы;
- `astro.config.mjs` — конфигурация Astro;
- `package.json` — зависимости, требования к среде и команды проекта;
- `package-lock.json` — точные версии и контрольные суммы зависимостей;
- `.nvmrc` — проверенная версия Node.js.
